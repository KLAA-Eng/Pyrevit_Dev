# Implementation Plan: Family Studio Green Browser And Supported Features

- Repository / evidence commit: `KLCode.pyRevit`, `e856ca3`; design source: `Family Studio.dc.html` and this handoff's `README.md`.
- Owner / priority / scope: KL&A engineering, next after the shared design-system foundation. Command remains `KL&A Tools_dev.tab/05 DevSandbox.panel/Family Studio.invokebutton`.
- Status: `NOT READY` for implementation until `00_design_system_implementation_plan.md` checkpoint 1 passes and the material decisions below are made.
- Outcome: replace the imperative, native-looking catalog browser with the FS-1 green WPF browser and support the already-approved Family Studio catalog, load/place, batch, refresh, tags, duplicate-preference, and local-root workflows.
- Non-goals: FS-6 vendor catalog integration; destructive duplicate resolution; shared catalog/root/tag governance; desktop Revit API indexing; production ribbon promotion; unapproved drafting-view support.

## Current Architecture And Constraints

- Current shell: `src/KLCode.FamilyStudio/Revit/KLCode.FamilyStudio.Revit/Views/FamilyStudioWindow.cs` owns rendering, filtering, detail, action handlers, and native `MessageBox` alerts. `FamilyStudioCommand.cs` owns command entry and a native configuration picker.
- Data/service contracts: `IFamilyRepository`, `FamilySearchQuery`, `FamilyDetail`, `SqliteFamilyRepository`, and `IFamilyLoadService`. Existing repository tests already prove search facets, tags on ingestion, favorites/recent use, thumbnail/type detail, and non-destructive duplicate signals.
- Current schema permits only `content_kind='family'` in `SqliteMigrationRunner.cs`; `PLAN.md` and `SPEC.md` explicitly defer `.rvt` drafting views. Therefore the FS-1 Views toggle cannot be implemented as a live mode without a separately approved content/source/import contract.
- Refresh runs in the Revit API through `RevitLibraryIndexService`; its cancellation token currently reaches `LibraryIndexer`, but the shell calls it synchronously and gives no progress callback. Thumbnails are host-generated and cached.
- The current configuration contract requires `libraryRoots`, `databasePath`, and `thumbnailDirectory`; it does not define a canonical `%APPDATA%\\KLCode\\FamilyStudio\\library.json` path or atomic root editing behavior.

## Acceptance Criteria

1. FS-1 is a fixed `1180 x 740` green, keyboard-usable browser with list/grid layout, search, current supported facets, selection/detail, cached preview states, checked batch membership, and all approved actions bound to view-model state.
2. `Load`, `Load & Place`, favorite, copy path, open folder, and refresh preserve their current service/transaction behavior; load failures and refresh outcomes use green KL&A alert windows instead of native message boxes.
3. Batch load uses one Revit transaction group, continues no further after a failure, rolls back the group, and records recent use only for committed loads.
4. Tags remain local SQLite data; duplicate resolution records only a local authoritative preference and never deletes, renames, overwrites, merges, or auto-selects a family.
5. Root changes, if approved, edit only operator-owned JSON atomically after validation and never add machine paths to Git. Views/FS-6 stay visibly unavailable or omitted until their contracts are approved.

## Material Decisions And Dependencies

- Owner must decide the authorized Views source/index/import contract. Current `content_kind` enforcement, scanner, and V1 SPEC support families only; a toggle that cannot return real content must not be shipped as active functionality.
- Owner must define the type-editing scope: loaded project type only versus source-library family document, naming/collision rules, and the allowed duplicate behavior. The plan assumes project-local type edits because source-library mutation would violate catalog safety.
- Owner must choose the canonical root JSON location and save concurrency behavior. The handoff requests `%APPDATA%\\KLCode\\FamilyStudio\\library.json`, while current refresh accepts a user-selected full configuration that also owns database and thumbnail paths.
- Dependency: the shared theme/localization plan; Windows Revit assemblies; a disposable Revit project and local family fixture set for live actions.
- Release gate: all source tests `PASS`; current macOS Family Studio test command is `UNAVAILABLE` until restore runs because `Tests/*/obj/project.assets.json` is absent; Windows Revit 2024/2025+ compilation, packaging, and live validation are `UNAVAILABLE` here. The command remains DevSandbox until all are accepted.
